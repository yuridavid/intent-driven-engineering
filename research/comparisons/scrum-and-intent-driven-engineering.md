# Scrum and Intent-Driven Engineering

**Status:** Experimental comparison

## Working hypothesis

Scrum primarily optimizes coordinated human execution under limited work-in-progress and uncertain delivery.

Intent-Driven Engineering primarily optimizes the preservation of meaning through controlled transformations in an environment where implementation is increasingly automated.

| Scrum emphasis | Intent-Driven Engineering emphasis |
|---|---|
| Implementation effort is expensive | Clear intent and context are scarce |
| Sprint bounds human WIP | Readiness bounds safe execution |
| User Story supports conversation | Source Specification supports explicit transformation |
| Developer primarily implements | Engineer increasingly defines, verifies, and orchestrates |
| Planning Poker estimates effort | Readiness evaluates uncertainty, risk, and validation burden |
| Velocity indicates throughput | Flow, outcome, quality, and integrity provide evidence |
| Definition of Done closes work | Flow Integrity evaluates end-to-end preservation |

This is not a claim that Scrum has no value. The models optimize different constraints and may coexist.
